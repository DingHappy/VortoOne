# 桌面正式版灰度管理

发布管理员通过 `https://vortoone.com/admin/releases/` 管理灰度设备。设备在正式版的「版本管理」窗口登记后，可以收到分配给它的签名更新。管理页记录设备最后一次上报的运行版本、分配版本和安装状态。

## 更新授权

设备检查更新时，服务端根据登记凭据查找该设备的目标版本。只有目标版本仍启用、包含设备平台的签名包且高于当前版本时，才返回这一个版本。其余情况返回无可用灰度更新。设备下载时同时提交自己的凭据和短时票据，服务端重新核对设备、目标版本和暂停状态。桌面端校验安装包及版本的签名，并在安装前重新确认授权。

灰度候选包通过私有更新服务分发。验收通过、转为公开发布后，公共更新源按公开版本提供该安装包。

## 部署

选择一台服务主机存储 SQLite 和签名更新包。官网国内和海外节点的 HTTPS 配置分别引入 [nginx.conf](nginx.conf)，将 `vortoone_desktop_rollout` 指向同一服务。服务本机使用回环地址，两台主机之间使用受访问控制的私有网络。安装包和数据库放在站点静态目录之外。

在服务主机上创建私有的 `ROLLOUT_DATA_DIR` 目录，容器以 UID 和 GID `10001` 读取包并写入 SQLite。定期备份数据库和 `releases/`。发布服务使用 [compose.yml](compose.yml)，监听地址默认为 `127.0.0.1:8096`。跨节点访问时设置 `ROLLOUT_BIND_ADDRESS` 为受控网络的地址，并只向官网代理放行。

在安全终端输入发布管理员密码，用 `server.hash_admin_password` 生成 `ROLLOUT_ADMIN_PASSWORD_HASH`，放到服务主机受保护的 Compose 环境文件。对于含有 `$` 的哈希值，在环境文件里使用单引号。通过 `docker compose --env-file <环境文件> -f deploy/desktop-rollout/compose.yml up -d --build` 启动服务。

可以在装有服务依赖的 Python 环境中，从本目录运行以下命令生成哈希。

```sh
python -c 'from getpass import getpass; from server import hash_admin_password; print(hash_admin_password(getpass("发布管理员密码: ")))'
```

上线前从两个官网节点分别确认 `/admin/releases/` 能进入同一个管理后台。检查无管理员会话、未分配版本、跨设备票据和版本暂停时的拒绝结果。更新 API 走 HTTPS，并由官网代理关闭访问日志和共享缓存。

## 暂存正式构建

在签名机上按 [正式构建流程](../../frontend/DESKTOP_CHANNELS.md) 生成并验签候选包。将构建输出的 `channel/stable` 目录交给暂存脚本。

```sh
node deploy/desktop-rollout/stage.mjs <stable 构建目录> <灰度暂存目录>
```

默认暂存 Apple Silicon Mac 包。已有同一版本、同一提交的 Windows x64 和 Ubuntu amd64 签名产物时，可以加 `--all-platforms`。脚本核对正式构建证据、校验和和版本绑定签名，然后写出 `releases/<版本>/`。版本目录的内容在暂存后固定。

将该目录复制到服务器数据目录的 `releases/.incoming-<版本>/`，设置目录和文件为服务账号可读，再在同一文件系统中重命名为 `releases/<版本>/`。管理页即可选择该版本。候选包验收通过后，可以用同一批构建产物走公开发布流程。

## 分配与停止

1. 在管理页生成一次性登记码。在目标设备上的正式版安装包中打开「版本管理」，填入登记码和便于识别的名称。
2. 选择候选版本和接收它的设备。只有具备相应平台安装包的设备可选。在设备上检查更新并确认安装。
3. 刷新管理页，核对设备上报的运行版本和检查时间。安装失败和取消会显示为相应状态。
4. 暂停版本、取消分配或撤销设备可停止后续授权。已经安装的设备可分配版本号更高的签名修复包。

已有公开版需要先用签名的正式安装包覆盖安装一次，才能完成首次设备登记。升级前可以通过桌面偏好设置备份现有工作区。
