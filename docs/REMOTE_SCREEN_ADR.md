# 远程观看与人工接管

实施前草案，依据 [#898 第 5.6、7.5 和 10 节](https://github.com/DingHappy/VortoOne/blob/c1f43e82cc770b98e270245558ad6cb68d9b6ae9/docs/HOME_AND_MEMBERS_DESIGN.md)。

当前 [网站人工接管](WEBSITE_HANDOFF.md) 依赖用户和浏览器位于同一台电脑。主分支已有连接器身份和文件通道。远程屏幕需要独立的数据连接，先实现浏览器，再考虑整个桌面。

## 授权

- 家从真人登录会话取观看者身份，从运行端登记取角色负责人和发起人，从设备授权记录取配对人。实际观看和接管前还要核对屏幕与当前回合、设备及连接代次的绑定。浏览器状态接口只查五档级别和角色可见性。
- 电脑由配对人通过本机设置决定是否向团队共享。未共享时，只有配对人可以打开屏幕，仍要满足级别要求。管理员与空间所有者也受这一限制。配对、共享或屏幕绑定记录缺失时拒绝打开。
- 五档按最高身份组合并。自己的范围由可信的角色负责人、配对人和发起人记录确定。自己的浏览器允许在该范围内看浏览器。自己的电脑还可看该范围内的桌面。所有浏览器继续保留自己的桌面权限。所有电脑允许团队范围内的两种屏幕。
- 观看默认为只读。人工接管单独确认并记录审计。登录请求交给资源主人或设计允许的团队审批人，且需要相同的屏幕权限。
- 打开观看、发送每批画面、转发每次人工输入和交还控制前都要复核当前会话、身份组、共享设置及连接代次。撤权断开观看并停止转发输入。

## 生命周期与数据

- 成员从自己的已登录会话为电脑生成单次配对码。授权绑定当前家的信任代次和当次成员身份，设备只出现在配对人的列表里。被移出空间后，现有连接和未使用的配对码失效。成员设备目前支持身份和在线状态，使用控制协议第 1 版。
- 电脑继续主动向家连接。屏幕使用独立、短时且绑定到已认证连接代次的授权。连接重建后重新授权。
- 只在有授权观众时传画面。画面和人工输入只转发给当前会话，留在内存。审计存参与者、设备、时间和结果。审计、模型上下文、任务记录和记忆均不接收画面、按键或登录凭据。
- 人接管时锁住该屏幕的角色输入。控制交还后，角色重新观察再继续。断线或撤权后，回合暂停等待确认。

## 验证顺序

先验证身份组授予和屏幕状态 API 的五档判断。浏览器数据适配完成后，再用两个账号核对私有电脑、角色归属、发起人、级别降权，以及接管期间角色停手和交还后重新观察。随后在分开的家与 Desktop 上验收一次登录接管，再验证整个桌面。

## 私有浏览器数据通道

家已接入只读画面转发。连接器为本机选定的浏览器窗口主动打开独立数据连接，每次开放绑定当前配对和控制连接代次，有效期五分钟。只有同源登录的配对人且具备自己的浏览器级别才能观看。家按观众的请求索取单张 PNG，限制尺寸、体积和频率。每张图在转发时重新核对会话、级别和配对。画面留在内存中，审计只写观看者和设备等元数据。

成员退出会话后停传画面。所有者现有登录共享同一个凭据，退出时会结束当前家中已打开的所有者预览。
