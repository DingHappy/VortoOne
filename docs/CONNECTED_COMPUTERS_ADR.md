# ADR-020：连接的电脑——家里判定，本机约束

**状态：已确认。日期：2026-11-17。所有者批准合并 #954 并按本 ADR 继续实施。**

首版采用本文提出的独立 TLS bearer、默认 30 分钟有界离线窗口、能力隔离验收后才开放，
以及恢复/搬家/重新认领后重新配对。当前 C1 的实现与验证范围见 [连接的电脑](CONNECTED_COMPUTERS.md)。

依据是 [#898 的设计文档第 5、10 节](https://github.com/DingHappy/VortoOne/blob/c1f43e82cc770b98e270245558ad6cb68d9b6ae9/docs/HOME_AND_MEMBERS_DESIGN.md)；
发起人规则沿用 [ADR-019](DECISIONS.md#adr-019回合带上发起人身份权限按发起人封顶2026-11-16)。
本文里的“身份组”对应旧设计给人分权限的“岗位”，agent 的岗位仍沿用原称呼。

## 1. 范围与实施前置条件

目标：放在别处的家，经电脑主动建立的连接，在本机明确开放的文件夹里读写；
未开放的能力由本机拒绝；内存不足时由家排队。聊天、记忆、定时和主任务台账仍只在家里，
不复制成第二个家，也不做双向数据同步。

已确认的边界保持：电脑不开入站端口；家里只有一个确认、污点与能力判定内核；
本机是只会收窄权限的第二道闸；新配对默认没有任何执行能力；已有登录凭据留在各自机器上。

源码核对基线为 main b6c4dbe9；以下按当前合并记录与验收证据区分：

- #942～#950 已合；#951、#952 在核对期间先后合入。它们的源码合并不等于真机验收完成。
- #898 的设计 PR 尚未合并，本文以上述固定提交作为引用，不能使用 main 中不存在的相对链接。
- 第 1、2 步的 Tailscale 分享、连接链接、真实开机自启与每天备份仍未完成真机验收。
  Docker 自动升级回退、本机服务生命周期与共同升级机制的遗留范围也需明确记录。

本 ADR 可以先讨论；**批准 ADR 不代表第 1、2 步已经验收**。第 3 步运行代码 PR 要等前置步骤
合并并完成对应验收，或由所有者明确调整落地顺序后再开始。不开 server-v 标签，不升级既有主机。

本阶段先服务个人所有者。身份组、团队共享电脑权限沿既有设计保留接口，但等第 5、6 步再开放；
远程观看和接管是第 4 步，Linux 独立系统用户是第 7 步，均不混进本阶段。

## 3. 拟采用的运行与连接方式

连接器是现有打包运行时中的独立工作进程，随自有 Desktop 安装和升级；
Rust 外壳只管理本机配置、秘密存储和进程生命周期。连接器不运行新的主 agent，
不读取家的模型密钥，不下载家下发的脚本或工具实现。无 Desktop 的运行方式另做交付验收。

电脑向明确选定的家主动建立 HTTPS/WSS 连接；远端地址必须使用有效 TLS，不提供“跳过证书校验”。
只有经本机可信宿主核对的同机回环通信可以例外。Tailscale 是默认接入方式，公网地址属于高级配置。
连接器不开放本地 HTTP、WebSocket、调试或任意转发入口。

采用一条有界控制连接和按需的独立文件传输连接。控制连接承载 hello、能力摘要、
动作准备/开始/取消、执行状态、结果 ACK 与心跳，不把大文件或屏幕流塞进心跳通道。
重连使用带抖动的退避，建议从 1 秒增长到 60 秒上限；连接恢复不等于任务重做。

沿用 #948 的区间兼容思想，但电脑协议独立声明支持的最小/最大版本和功能集，
不把现有 Web API 的 api/minApi 数字当成电脑协议兼容证明。只有区间相交且必需功能齐全才进入可调用状态；
无法识别的协议、动作、能力或必填字段拒绝，说明哪一侧需要升级，不能退成裸命令或旧手机协议。

每次连接有新的 connection_generation；同一配对只接受一个当前连接，替换时 fence 掉旧连接。
补报旧任务要同时带原执行身份和当前连接身份，由家查原调用登记，不能把旧动作改装成新动作。

## 4. 配对、秘密存储与撤销

### 4.1 配对及稳定身份

由已经认证且有权的真人在家里生成配对码；agent 只能提出连接建议，不能生成、消费或批准配对。
提案默认是随机 12 位 Base32、5 分钟有效；每码最多 5 次失败，并另限制来源及家级请求速率。
持久化只存摘要和过期信息。核对、消费和建立授权在同一持久化临界区完成，并发消费只能有一次成功。
失败或重启不得把已经消费的码变成可复用码。

在本机受信任设置窗口中，用户确认规范化地址、家身份和电脑名称后输入配对码。
普通应用连接链接、远端网页和模型输出不能触发机器配对、安装或本机权限变更。

授权绑定以下身份，彼此不能互相代替：

| 字段 | 来源与作用 |
| --- | --- |
| home_instance_id | 沿用现有持久实例 UUID；提取公共身份读取/迁移入口，保留既有值，不用本机绝对路径派生 |
| paired_principal_id | 由家的已验证登录和稳定 subject 得到；个人所有者需先补不可变 owner subject，不接受邮箱或网络帧自称 owner |
| connector_id | 一次明确配对的持久电脑授权身份，重新配对生成新值；本机 installation_id 只作安装元数据，不用于网络认证 |
| credential_epoch、trust_epoch | 配对授权代次及家的电脑信任代次，撤销、恢复和重新认领时用于失效旧授权 |
| local_policy_revision | 本机权限修订；任何本机收权后，旧动作预览和旧授权均须重新核对 |

已有家在其原有可信所有者认证通过后，一次性原子建立稳定 subject；同时覆盖已认领账号的家和
仍使用本机 owner-key 的既有个人家，不能按邮箱、名字或账号服务归属猜测合并。
并发初始化和重启必须保持同一个 subject，普通资料修改不改变身份；迁移失败拒绝配对，不回落到路径 ID。
尚未认领的新安装仍须完成原认领流程，不能仅因存在 owner-key 文件就被视为已认领。

家在本机时，可由可信启动器通过已有受控 IPC 传递短时、单次、本机进程绑定的票据自动配对，
不从公开端口按 IP 认领，也不复用所有者令牌。**自动配对仍默认全关**，不把已有本机工具权限暗中转为远程授权。

### 4.2 凭据方案：独立随机机器令牌

首版提议采用 256 位随机 bearer，独立于手机令牌、所有者密钥、登录 cookie、账号读取租约和模型密钥。
令牌只在配对响应中返回一次；家只持久化摘要，重连在 TLS 认证头中提交并核对当前撤销状态。
它只允许建立这一台电脑的控制连接、补报其原动作和使用其绑定的文件传输记录，不允许管理家、成员或其它电脑。

这是 **TLS bearer 方案，不是设备私钥证明**：家在认证时会短暂接触明文令牌；
摘要不能用来反推出密钥，更不能设计成家用原令牌对命令做 HMAC 签名。
泄露者在撤销前能冒充这台电脑、接收派给它的任务并伪造结果。若所有者不接受这个残余风险，
应在首个实现 PR 前改为本机生成密钥对、家保存公钥、重连挑战签名，并单独核对依赖及兼容性。

本机秘密使用独立的系统秘密存储项，名称显式隔离应用通道、home_instance_id 和 connector_id，
不靠 debug/release 编译标志区分正式版与 Dev。没有可用系统秘密存储时，
仅允许本机明确确认的 0700 目录/0600 文件回退，并在界面显示降级；不能静默明文回退。
秘密不进网页 localStorage、命令行、URL、普通日志、模型上下文或家的备份包。
本机删除配对时删除秘密；令牌轮换采用真人在家撤销、在本机重新配对，不让机器令牌自行扩大或重建授权。

### 4.3 撤销、恢复与离线边界

家里移除电脑时，先持久化撤销并增加授权代次，禁止新的调用，再经当前认证连接发送撤销/取消通知。
本机持久记下撤销、开始尽力取消后返回 ACK；家只作有限等待后关闭连接。
通知没送达或没 ACK 时显示“本机停止结果未知”，不能把关闭连接等同于已停止任务；单纯断连也不能当作撤销。
握手、发动作、接收补报和取文件都重新核对授权。
本机关闭能力、删除文件夹或移除配对立即收权，不等待家回复。在线正在执行的动作尽力取消，
只有确认进程结束才释放资源；已经产生的副作用不会因“取消”自动撤销。

**离线电脑不可能即时知道家里的撤销。** 为兼顾设计要求的“断线后长任务继续”，提议：
只有 started 的既定动作可继续到本机已经批准的期限，默认最长 30 分钟离线窗口；
更长窗口必须由本机真人显式选择，家和模型只能缩短，不能扩大。离线不接受新动作、不新增批准，
需要后续交互/凭据/权限的阶段停下等待。若需要“一撤销就必停”，应选择失联停止模式，
不能同时承诺不受限制的离线继续。

家的恢复、搬家、所有者重新认领或转让不得复活旧电脑授权。
在重新开放电脑通道前更换 trust_epoch、清除活动连接及待配对码，使全部电脑重新配对；
恢复后的旧授权摘要只能作为失效记录，不能直接重新启用。相关恢复钩子是首个配对 PR 的验收项。
这不改变其它既有凭据的备份约定；实现时新增电脑信任的失效规则，并测试升级失败回退的兼容性。

## 5. 一次调用如何通过两道约束

1. 家的可信宿主从原会话、任务和已验证的发起人装配目标电脑；模型参数可以提出目标，不能创建身份或权限。
   仍先经过原 ToolRuntime 的参数、能力档案、deny、模式、Hook、预算与确认路径。
   不把 external、owner_device 或无人值守入口改标为 local 来取得更多能力。
2. 需要预览的写入/执行先做无副作用 prepare；本机只返回目标资源身份、版本和预览所需事实，
   内容仍作为外部来源。读取也须通过本机读权限，prepare 本身不能写入、执行或自动放宽权限。
3. 家在原确认门冻结具体动作。预览必须显示目标电脑、文件夹别名、操作、内容/参数摘要和覆盖版本；
   同时绑定发起人、家/电脑身份、task/turn/call、授权代次、本机策略修订、期限与预算。
4. 确认通过后，受信任适配层才形成有界调用信封。只传固定动作名、经过校验的参数和上述绑定，
   不传 Tool、PreparedToolCall、ToolExecutionContext、Python 对象、回调或“approved: true”来跳过内核。
   传输认证和授权来源于这条已认证连接及家的原调用登记，不来源于模型可写字段。
5. 本机重新检查配对、当前代次、能力、文件夹及资源版本；只执行本机固定登记的适配器。
   任何一层拒绝即结束。本机没有“重新批准家已拒绝动作”的入口。
6. 结果走原 ToolOutcome 与执行报告适配。文件内容、命令输出、网页文字及包含这些内容的错误，
   在家里由适配器强制附加外部来源并传播污点，不接受电脑返回 untrusted=false 清除。
   网络解析前限制大小，不能把 ToolRuntime 最后的文本截断当作网络输入保护。

**物理路径由目标电脑解析。** 信封使用本机登记的 folder_id 加相对路径；
家里的绝对路径、repo_root、inode、SandboxDecision 或 isolated=true 均不是本机事实。
文件访问逐段核对目录句柄/等效平台约束，禁止符号链接逃逸与父目录替换竞争。
写入先落本机同文件系统临时文件，再完成预期版本、SHA-256 与提交条件校验；
原文件已变、权限已撤销或无法证明目标身份时拒绝覆盖，不能只做一次字符串 resolve 后继续写。
临时目录 0700、文件 0600，最终文件权限由本机策略决定，不接受远端 chmod/chown。
**普通 rename 不是原子条件覆盖**：实现必须说明如何保护版本条件直到提交。
首个文件 PR 至少安全支持排他新建和返回补丁；普通目录无法证明覆盖条件时拒绝直接覆盖，
不能承诺“先检查版本、再 rename”即可避免并发编辑丢失。受控目录或版本化条件提交另有行为验收。

### 本机能力与命令隔离

文件读、文件写、命令、浏览器、Codex 分别默认关闭；文件夹、允许的程序、出网、凭据可用范围、
运行时长和并发上限由本机真人设置。家只能看到必要的能力/资源别名和可用状态，不能修改这些设置。
入口提议为 Desktop 的“设置 → 这台电脑 → 连接权限”，仅本机打包窗口提供；
扩大权限需原生确认/选择文件夹，不能只凭网络字段或可静默调用的网页 IPC 修改。
远端网页只能显示“需要在目标电脑上开放”，不能调用本机开启接口。
尚无安全适配器的能力显示未就绪，开关不能让一个未实现的能力变成可执行。

文件工具的路径围栏不能约束任意子进程。**命令能力须等新的本机隔离约束验收后才开放**：
实际读取、写入、网络、继承环境和登录凭据的可用范围都要被限制；
本机自己选择后端和 profile，核对 allowed 且 isolated，家不能传 sandbox=off、后端名称或任意环境来降低底线。
现有本机显式 off 的兼容语义不能被远程入口继承为绕过途径。缺少安全后端的平台明确拒绝。

不把“SSH 私钥/CLI 登录没有上传”等同于“凭据不能被间接使用”。
打开 Codex 或带登录的浏览器也可能代用户使用账号，其适配器需单独约束能力、网络与交互范围；
未完成前保持关闭。观看与接管仍等待第 4 步 ADR，Linux 独立系统用户仍按第 7 步实现。

## 6. 断线、去重与按内存放行

家的主任务仍用原台账；连接器仅保存本机动作日志和待确认回执，不保存聊天、记忆或第二份任务计划。
本机日志按 home_instance_id、connector_id、trust/credential_epoch、action_id 建键，
记录参数摘要、发起人、策略修订、期限、执行引用与接收/开始/结束状态。先把 started 耐久写入再启动副作用。

同 ID 同摘要返回原状态，不重复执行；同 ID 不同摘要拒绝。
家在发送前持久化派发意图，丢 ACK 时查询原动作；只有能确认从未开始的调用才可在原授权期限内重新送达。
已经 started、执行结果不明或崩溃在开始边界的动作标记 unknown/possible，由人核对，
不把“没看到结果”当作“没有执行”，也不自动转交另一台电脑重做。

断线不终止已经获准且仍在期限内的本地进程；控制连接与工作进程生命周期分开。
本机进程重启、系统关机与单纯断线不同：恢复时核对日志和进程身份，无法证明仍在运行就记未知，
不靠复用 PID 猜测，也不自动重新启动动作。

终态和有序报告先写持久 outbox，家持久接收后才 ACK，电脑收到对应 ACK 后才回收。
重复报告只回相同 ACK；冲突前序、旧代次或参数不符不覆盖当前状态。重连可通过当前授权连接补报原执行，
但新连接不能凭一个旧 action_id 取得新的执行权。执行结束、结果已送达与所有者验收完成分别显示。

本机在实际开始前原子预约资源，使用可用内存而非仅看总内存；预留系统余量和已有运行任务的预约。
预算由本机适配器设下限，家可以申请更多，不能以更小的数绕过本机上限。内存不足返回
“暂时没有位置／尚未开始”，家保留任务并排队，真人等待优先于后台，只影响未开始的任务。
连接器不维护顺序队列，不因断线就释放仍在运行的任务所占资源。
读不到内存时使用本机固定并发上限，提议默认 1；这是准入估算，不承诺任意命令运行中绝不会超内存。
取消和重试均复用原任务的明确动作，不靠后台无限轮询自动推进。

## 7. 文件传输与建议上限

小文件可随有界调用传输。大文件由家签发短时、单次、只对应某电脑/动作/文件版本的上传或取件记录；
电脑只访问家的传输端点，不接触对象存储的凭据、签名存储地址或任意第三方 URL。

票据只存摘要，秘密走认证头；请求前原子核对并消费，5 分钟是领取/开始的有效期。
成功消费后形成绑定原动作的传输会话，传输中检查撤销、本机策略及原动作/本机批准的总期限，不能无限续期。
内容边读边算哈希，限制声明及实际字节数，并核对临时空间配额；结束后大小和 SHA-256 均一致才改名，
失败保留原文件并清理该次临时文件。传输哈希证明字节一致，不证明内容可信、无害或任务完成。
断线后旧票据不能重用；在原动作授权和资源版本未变时另领新票据，首版不承诺断点续传。
新票据仅允许为同一动作重传字节；最终提交仍受原动作日志去重约束，不获得第二次执行或覆盖的机会。
上传/下载均不能隐含执行文件、扩大目录权限或获得一次新的写入批准。

以下是本 ADR 的拟定默认值，实施时以版本化合同和双端测试固定，不能由远端随意提高：

| 项 | 建议值 |
| --- | --- |
| 控制帧编码后的最大大小 | 256 KiB |
| 随帧文件的原始字节上限 | 64 KiB |
| 单次大文件传输 | 1 GiB，流式处理且另受磁盘/动作预算约束 |
| 文件正文进入模型上下文 | 32 KiB，更大时明确截断/分段，不继承传输上限 |
| 单次配对码、文件票据有效期 | 5 分钟；传输动作另有本机批准的总期限 |
| 初次无法读取内存时的固定并发 | 1 |
| 断线后既定动作的默认最长继续窗口 | 30 分钟，且不超过该动作已经批准的期限 |

## 8. 威胁与损失上限

| 情况 | 防线 | 必须承认的剩余风险 |
| --- | --- | --- |
| 家被攻破或发出越权动作 | 本机能力全关、文件夹/程序/网络/凭据范围与预算独立核对，实际 OS 约束 | 家仍能在本机已开放的范围内滥用能力；只开放文件夹不等于限制了任意命令 |
| 机器令牌泄露、连接器被冒充 | 独立作用域、TLS、摘要、撤销代次与实时断连 | bearer 在撤销前可被用于假冒、接收该电脑任务及伪造报告，不能证明物理机器或结果真实 |
| 配对码被猜测、重复消费、假家诱导配对 | 随机码、短时、限速、原子消费；本机确认地址与实例身份 | 真人仍需核对选中的家；网页链接不能代替本机确认 |
| 重放、丢 ACK、伪造乱序报告 | 固定动作摘要、持久 started/outbox、代次与前序核对 | 不能保证分布式副作用恰好一次；不明就停在未知，不能自动重做 |
| 外部文件/命令输出夹带指令 | 在家中强制来源与污点，原确认门继续生效 | 可信电脑返回的内容也不能当作可信指令 |
| 本机进程/系统管理员被攻破 | 私有状态目录、系统秘密存储和最小资源授权 | 本 ADR 不能防住控制该 OS 用户或内核的攻击者 |
| 恢复旧备份、所有者换人 | 恢复/搬家/重新认领前置失效全部电脑信任 | 需要重新配对，不能以恢复后的旧摘要悄悄重新放行 |

## 9. 拆分 PR 与验收

在前置验收及本 ADR 获批后，每一项单独审查、通过后再进入下一项。下表是拟定实现边界，不是已有能力。

| PR | 变更边界 | 必须验收 |
| --- | --- | --- |
| C1 身份、配对与主动连接 | 公共持久家身份、稳定所有者 subject 迁移、独立电脑授权、协议区间、可识别的撤销通知和恢复失效；没有执行能力 | 原有 owner-key/账号家均能安全迁移；并发/重启不更换 subject；未认领拒绝；码过期/并发消费只一成功；机器令牌不能访问主人 API；移除与恢复旧备份后不能再连；本机自动配对仍全关 |
| C2 本机文件夹与小文件 | 原 ToolRuntime 中的目标适配、本机权限窗口、受限读写、污点；副作用前就具备派发意图、耐久 started/终态、摘要去重和最小回执 outbox；本机并发先限 1、有界 in-flight | 远端家在明确开放目录读取/安全新建；目录外、链接/父目录竞争、无法保证的条件覆盖和远端改权限均拒绝；关闭本机能力立即生效；丢 ACK 不重复写入，提交边界崩溃保持未知 |
| C3 准入、断线与补报 | 在 C2 既有日志/去重之上扩展长任务、原任务排队、动态内存预约和跨重启有序补报；不新增通用执行池 | 内存不足尚未开始且任务在家排队；真人优先；断线不断期限内已有动作；丢 ACK/重连/进程崩溃不重复执行；冲突补报拒绝 |
| C4 大文件 | 家代理单次传输、大小/哈希、临时落盘与配额 | 跨电脑、跨动作、过期、复用票据、错哈希、超限、断线及中途撤权均拒绝；原文件保持；模型正文上限不随文件增大 |
| C5 命令及各专门适配器 | 本机更窄的 OS 约束、环境/程序/网络/凭据范围，复用原执行路径 | 未开放/无安全隔离均拒绝；不能读取或写入范围外资源、继承秘密或绕过出网限制；审计绑定原动作；浏览器/Codex未就绪时保持关闭 |

新增路由同步更新路由基线；协议增加双端边界与重放行为测试；新环境变量登记 ENVIRONMENT.md。
依赖、安装包及升级兼容性在各实现 PR 单独验证；所有测试离线、确定性。
Mac 和 Linux 分别进行真实主机验收，不把模拟协议/沙箱测试视为物理隔离或真实接入已经通过。
第 3 步验收至少完成设计里的远端指定目录读写、关闭能力拒绝和内存不足排队，再讨论第 4 步观看接管。

## 10. 未采用的做法与已确认的决定

未采用：给电脑开入站 SSH/HTTP；让远端提供工具对象、代码或无条件 confirm；借用手机只读令牌；
同步两个家的聊天和主任务；依赖“进程退出码为 0”证明业务验收；把现有命令沙箱原样当作完整读/凭据隔离。

所有者已批准本提案，以下四项作为实现依据：

1. 首版采用 TLS bearer，保留上表的假冒残余风险；设备私钥签名不在 C1 中实施。
2. 断线已开始动作默认最多继续 30 分钟，在线撤销尽力取消；不承诺离线即时撤销。
3. 任意命令须先完成严格本机读/写/网络/凭据隔离；未就绪时命令、浏览器和 Codex 保持关闭。
4. 家恢复/搬家、所有者重新认领或转让后，所有电脑重新配对，不能恢复旧授权即自动重连。

确认只使本 ADR 成为后续实现依据；不自动授权发版、部署、修改凭据或改变既有主机。
