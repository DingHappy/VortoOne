# VortoOne 前端改版

主人决定，2026-11-14：所有界面统一学习 agentes.chat 的界面和操作形式；专员不再设独立的展示页，按统一角色入口呈现。保持 VortoOne
现有许可，独立实现。不迁入其组件、样式、图标、品牌素材或后端。

## 范围与原有合同

继续个人模式：每个运行端一个个人空间，里面管理多个明确登记的项目。
Desktop 先完成完整流程，手机使用共同变量，并按原生交互单独适配。
公司多人互联继续保留为后续方向，不在本次自动开启。

原会话、任务、岗位、审批、调度、记忆和制品仍是权威来源，不增加第二套记录或连接状态。
切空间继续核对原连接代次，未发送内容留在原会话；旧项目归属未知继续保留未知。
主人确认、污点、岗位校验、禁用动作、审批轮次/实例、无人值守默认拒绝保持原规则。

## 顺序与验收

| 批次 | 页面和行为 | 验收要求 |
| --- | --- | --- |
| F1 | 共同设置组件、安装引导、设置分组与保存位置 | 本机和远端合成流程可走通；失败可返回；未确认不安装；旧目标失效可见。 |
| F2 | 空间、侧栏与主界面 | 日常入口清晰；同名空间可辨认；切换不串草稿、回包或审批。 |
| F3 | 消息、输入、执行过程和结果 | 状态、失败和下一步可见；技术详情按需展开；流式更新不抢焦点。 |
| F4 | 角色、小组、例行工作、资料库与连接 | 每个现有操作有明确入口、状态和结果，使用原授权和领域服务。 |
| F5 | 手机与完整验收 | 共同变量生成物一致；按真实中文、窄窗口、深色、空数据、长列表和失败核对。 |

按可审查范围分 PR。第一批落共同组件、F1/F2 的 Desktop 基础，以及 F3 的单工具摘要；
F4 先接通原页面入口，页面内部的完整改版与 F5 手机布局仍待后续。未完成就保留未完成，不把组件夹具、合成回执或截图当作已安装产品的
真实使用验收。合并、发布和部署需要主人另行授权。

## 呈现规则

- 共用分组、设置行、字段、状态与详情，不在每页重新定义同类控件。
- 正文先说明当前任务或结果。用途说明可展开；错误、目标失效、操作后果和等待确认
  保持可见。原确认仍展示作决定所需的信息。
- 安装先选位置，再准备缺项。模型配置已保存只说明保存，不代表推理或工具已验证。
  本机运行由主人点一次「开始」，依次安装、启动、连接并逐步显示（2026-11-15 起，见「首次引导」）；复制模型配置仍需主人先同意。
- 设置在主区打开，按账号、个人空间、模型与执行、连接与工具、高级与关于分组；组内用横向分类。搜索覆盖全部设置，直接定位可以展开对应分组；
  切分类保留原草稿。诊断身份放连接详情，当前空间与各项保存位置保持可见。
- 颜色、字号、圆角、间距与尺寸来自 `design/tokens.json`。按钮使用明确动词；
  不把执行结束写成验收通过，不把已发送写成已完成。
- 侧栏区分日常入口与会话：主要聊天、工作动态、定时工作、资料库和更多；下面按频道、角色、小组与旁聊分组。角色直接显示实际登记名录，不另设专员主导航或形象展台。
  日常页复用原组件与记录，对话右侧仍可回查相同资料，不恢复已退役编码工作台。

## 首次引导（2026-11-15）

主人决定：除角色形象外，配置流程和样式都照 agentes.chat 做。首次引导按它桌面端的首次运行重排
（源码参考 `50ca784` 的 `apps/desktop/src/windows/FirstRun.tsx`，只读学习，独立实现）：

- **选择运行位置**：左边是画面，右边是两个单选行和一个按钮；画面和按钮文字跟着选择变。按下按钮前不保存、不启动任何东西。
- **在这台 Mac 上**：核对本机状态 → 接模型（已保存则只显示一行）→ 勾选同意复制模型配置 → 点一次「开始」。
  之后进入进度页，依次安装、启动、连接，每步有标记和用时；失败停在那一步并写明原因，可返回或重试。
  取消只在两步之间生效，做完的步骤保留。已装过的直接「启动并连接」，不再要模型和同意。
- **连接另一台电脑**：已登记的助手列在上面可直接使用，下面是原来的地址与令牌表单。
- 每页左上有返回「运行位置」的链接，Esc 同样返回；原来的三步进度条、页脚说明和「如何选择」折叠说明去掉了。

这改掉了此前「安装、启动、连接各自由主人操作」的做法。没变的：未同意复制模型配置不安装；初次安装不开定时作业；
每一步前重新读取状态，连接前核对登记身份和运行实例，不自动重试任何写操作（`desktop/src/lib/localSetup.ts`）。
设置页里的本机常驻助理卡片仍是分步操作。agentes 的「云端」选项和局域网自动发现没有对应能力，没有做。

离线核对页：`desktop/qa/runtime-onboarding.html`（合成 IPC，不会真的安装）。截图见 `docs/design/first-run/`。

## 统一角色与全界面参考（2026-11-14 补充）

所有新改页面都沿用同一视觉和操作依据，不为某个领域另起一套产品样式。
当前参考的落点如下；“入口已接通”不等于内部全部重做。

| 路径 | 共同形式 | 现有实现与边界 |
| --- | --- | --- |
| 安装、引导、运行位置 | 先选择在这台 Mac 运行或连接已有电脑，再逐步处理缺项、模型与确认 | 保留原 RuntimeOnboarding / LocalResident 的显式安装、复制配置与失败返回，不因改版自动安装或启用调度。 |
| 个人空间、聊天、频道 | 全局搜索栏、空间侧栏、圆角主区；频道和角色分组；消息身份清楚 | 复用原空间、SID、输入草稿与频道操作；不增加第二套 workspace 或聊天库。 |
| 角色会话与资料 | 侧栏点击角色直接进入工作会话，页首身份打开共同资料弹层 | 工作会话投影原 StaffService / CollaborationService 任务；没有第二份聊天库。总助手仍打开主要聊天。资料使用原 StaffSnapshot。 |
| 添加角色 | 名字、已登记分工与执行方式；核对后保存提议，再由主人明确批准 | 复用原 StaffApprovals，批准前不登记，批准后打开角色会话但不派活。岗位权限来自登记，表单和消息都不能附带权限。 |
| 全局设置 | 主区内的紧凑分组导航、横向分类、分组表单与按需详情 | 所有既有设置页可达，保存位置和目标失效明确展示；搜索、切分类保留草稿，离开需先处理未保存修改。 |
| 动态、任务小组、定时工作、资料库、连接与技能 | 沿用共同主区、标题、状态、分组行与详情规则 | 原领域页和操作入口继续可用；内部复杂表单按 F4 逐页迁移，不用截图代替任务执行或审批验收。 |
| iPhone | 共享角色用词、颜色和尺寸变量，按原生导航适配 | 本步只同步共同生成物，不声称 iPhone 各页面已重构或真机验证。 |

已选定的四个角色形象用于默认身份，已有自定义头像优先。形象不代表角色已经登记、启用或获准。
当前弹层固定打开时的资料快照；连接或个人空间变化后，旧内容仅供回查且禁止动作，需重新打开。
添加角色时的权限方案也固定在原目标，避免旧窗口展示另一个空间的新方案。

## 角色工作主线（2026-11-15）

继续按主人选择研究 agentes.chat 的页面结构和操作流程。本批源码参考固定为
`50ca784dd4c83efbc7ca916a6f07faa8accfe7f6`：`DmPage`、`AgentPage`、`Sidebar`、
`NewAgentDialog`，以及 `packages/ui` 的 Message / Composer。只读学习；官方组件仅在仓库外的隔离参考页渲染，
不进入 VortoOne 的生产构建、依赖或发布产物。现有 Apache-2.0 保持不变，角色继续使用主人选定的史莱姆。

- 角色会话中的每条新任务使用既有协作子任务和共享执行池。发消息明确表示交给当前角色处理一件事；
  默认交付方式为主人验收。执行结束、等待动作批准、结果待验收、已验收分别呈现。
- 派活核对当前成员、岗位完整摘要和修订、运行实例；验收和补充要求核对任务摘要、轮次和实例。
  所有新增写路由仅接受配置主人令牌的 owner 入口，审计先于放行。原岗位校验、污点、禁用动作和审批卡不变。
- 请求使用原始标识定位同一任务；发送回执丢失时保留原文和标识，先只读核对，不自动重新派活。
  任务历史分页并明确标记读取不完整。回查旧页时暂停自动刷新，手动刷新回到最新记录。
- 未发送文本只保存在当前窗口，按个人空间和角色隔离；切角色、切空间或连接代次变化，不把旧请求送往新目标。
  创建表单在服务不支持新版接口时提示更新；工作会话接口读不到时禁止派发，不退回到自动向主要聊天发送草稿。
- 创建角色只选已有且启用的岗位，执行方式同时遵守原 D10；自定义新岗位仍走原角色与权限流程。
  创建表单复用原提议的 digest / nonce / round / instance；审批结果回读确认登记后才打开会话。

离线页面验收：先运行 `desktop/qa/role-conversation-server.py`，再启动 QA Vite 并打开
`/qa/personal-roles.html`。服务只监听回环，资料放新临时目录；使用真实 HTTP 客户端、主人路由、领域服务和任务池，
执行器返回明确标注的离线示例，不连接模型或外部通知。`/qa/finish` 显式交回结果，
`/qa/lose-receipt` 用于验证已受理但回执丢失。此夹具不能证明真实模型、原生安装或手机已验收。

本批范围是角色工作主线，不宣称全应用已经逐页复刻；安装引导、资料库、例行工作和手机的完整对照继续按 F1～F5 分批完成。

实际应用截图可能包含个人资料，仅供本机核对，不上传仓库或 PR；提交的验收图全部来自真实组件和合成数据。
最新比较、修正与验证边界见根目录 `design-qa.md`。

## 2026-11-14：模型设置、例行工作与资料库

继续 F4，使用同一套列表搜索与筛选组件整理资料库和例行工作管理。
搜索只检查当前已读取的标题、专员名字等元资料；不读取正文，不增加服务端查询，也不修改记录。
资料库保留按天分组、原预览、版本选择和沙箱；筛选不关闭已打开的原资料，未匹配时明确提示。
读取失败和真正没有资料使用不同状态，旧内容保留并标明读取未完成。

模型服务以分组标题、文字行和原动作呈现；配置回执使用已载入、需重启、待核对三种真实数量，
具体工作区和证据边界可展开，失败或版本变化不沿用旧成功。密钥、保存、冲突和原生确认路径保持。
例行工作先列当前登记的排期，再放默认时区与迁移设置；错误、在途任务、调度未开启和迁移中断提示不折叠。
原迁移仍须预览、提议和主人确认；调整时间仍只提交提议，删除仍有确认。

原批次独立基于 main；顺序整合时保留 #888 的聊天改进、现有“连接 AI”向导和 #893 的角色/频道流程。
原始视觉与合成行为记录见 `desktop/qa/design-qa-settings-collections.md`，整合验证单独记在 PR 说明。
