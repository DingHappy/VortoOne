# 连接的电脑

本批实现 [ADR-020](CONNECTED_COMPUTERS_ADR.md) 的 C1。所有者已批准 #954 并继续实现；
第 1、2 步的 Tailscale 分享、连接链接、真实开机自启与每日备份验收仍需单独完成。
合并源码不等于安装、部署或发布，本批不升级既有服务器。

## 使用入口

1. 在家的新版界面打开“设置 → 设备”，在“连接的电脑”卡片生成配对码。
   首次安装先完成所有者认领；只有确实属于你的旧家，才勾选“仅使用所有者密钥登录的旧家”。
2. 在目标电脑的自有 VortoOne Dev 菜单打开“连接的电脑…”，填家的 HTTPS 地址和电脑名称。
   先核对地址与持久家身份，再输入 12 位配对码，并在本机系统窗口确认。
3. 本机保存独立凭据并主动连接。家里可以查看连接状态、刷新、移除；本机也可移除本机登记。
   本机移除仅停止并删除这台电脑的凭据，家的登记应在家里另行移除；重新配对建立全新授权身份。

每码 5 分钟有效、单次使用，最多 5 次错误；新码替换旧码。码只保存在界面内存中，过期清除，
服务器只存摘要。机器令牌与所有者、成员、手机、MCP 及账号读取租约完全分开。

家就在本机时，自有外壳通过启动子进程的私有 stdin 交付短时票据：服务器核对真实父 PID，
外壳再次核对子进程仍存活、PID 和本机端口，再用票据自动登记“这台电脑”。票据绑定持久家身份和信任代次，只存内存摘要，
60 秒内单次，首次尝试后即消费；未认领或未明确迁移的旧家不自动认领，也不后台等待后补授权。
自动配对只使用系统秘密存储；失败可在本机窗口看到，不静默降级、不反复制造新登记。
本机移除或家里撤销后，重启 App 不会自动重建授权；需要在本机明确重新配对。

配对登记身份和连接状态，所有能力默认关闭。双方协商到 v2 后可使用下述文件流程。
原生窗口是文件夹授权入口。命令、浏览器和 Codex 帧仍会被拒绝。

## C2 的本机文件夹授权

在 VortoOne Dev 的“连接的电脑”窗口，选择对应连接的“本机文件夹”。读取和新建可以单独授权。
选中权限后使用系统选择器选择目录，再核对家的地址、目录与权限。授权列表可以撤销任一目录。
原生窗口显示目录真实路径供用户核对。家里只能看到别名、编号和权限。
授权绑定本次配对和文件夹身份，新配对需要重新选目录。目录被替换或移到别处后需要重新授权。

文件夹授权完成后，在已认领的家中以所有者身份打开主要聊天，提到目标电脑、目录和文件名。
例如“读取工作电脑上资料目录里的 notes.txt”，或“在资料目录新建 summary.txt”。确认卡会显示电脑、
目录、相对路径、文件版本，以及写入文本的大小与摘要。每张卡只批准这一次。新建也遵守聊天原有的
plan 到 build 授权。手机、成员和后台任务沿用各自现有权限。

家在发送新建请求前持久记录动作。断线时如果结果尚未确认，助手会给出动作编号。可以在主要聊天按编号
查询。电脑重连后补发回执，家持久接收后才确认收到。回执重送不重做原写入。

## C3 文件动作的资源等待

电脑在共用的文件执行锁内检查可用内存。首批为系统预留 128 MiB，读取和新建另预留 8 MiB，
差异预览另预留 32 MiB。系统无法报告可用内存时，仍由执行锁保持全机一次一个文件动作。

内存不足或执行锁被占用时，电脑回复「尚未开始」。家在原聊天回合显示等待状态，并在本次批准的
90 秒内按同一编号、摘要、目标和版本重试。每次派发前重新核对连接与授权，电脑也重新检查本机目录。
停止回合、换连接或批准到期都会结束等待。派发时连接中断、结果无法核对的动作需要按编号查回执。
等待记录只存动作标识和摘要，家的进程重启后需要重新在主要聊天发起。

文件执行使用电脑侧的独立工作槽，每次由固定入口启动一个子进程。配对绑定和已批准的文件动作经私有管道
交付。子进程重新核对目录授权、文件版本与期限，沿用本机执行锁和持久日志。机器令牌留在连接器。

普通断线时，控制连接可以重连，已开始的文件动作可在原期限内完成，结果从持久回执队列补报。在线撤销、
父进程退出或期限届满会关闭私有管道，子进程在发布文件前检查管道。进程崩溃后，已有终态可以补报，
只有开始记录的动作保留为未知。执行锁由子进程持有，恢复时无需凭旧 PID 推断动作或补做写入。
当前适配器处理的是小文件。大文件流式传输和更长的专用任务继续按 ADR 分批接入。

本机执行器最多处理 32 KiB 的 UTF-8 文本。读取固定到预览过的版本。新建绑定预览时的父目录，
用排他发布保留现有文件。新建仅直接写入用户选定的目录，子目录需要单独选择和授权。
补丁需要同时具备读写权限，只返回差异，原文件保持原样。
逐段使用目录句柄，拒绝符号链接、有多个硬链接的文件、特殊文件、已知凭据路径及无法核对的平台。
动作以配对身份、编号与参数摘要去重，写盘前先持久登记开始状态。进程中断后结果不明的动作
归为未知，重试不会重新写入。同一台电脑一次只处理一个文件动作。

## 连接与凭据

- 电脑不监听端口，只向明确确认的家建立 HTTPS/WSS。TLS 验证不可关闭；拒绝 HTTP/WS 重定向，
  机器凭据不跟随重定向，也不使用环境代理或环境注入的 CA。
- 只有由自有外壳证明属于当前本机后端的字面回环地址可以用 HTTP；不能仅因 IP 是回环就放行。
- Mac 使用原生系统钥匙串，服务名显式包含 Dev 通道；不靠 debug/release 标志隔离。
  系统秘密存储不可用时需本机真人再次确认，才允许 0700 目录/0600 文件降级，并在状态中标明。
  本批其它平台没有宣称已有原生秘密存储适配；文件回退仍需明确确认。
- 秘密只在父子私有管道传递，不返回网页，不放入参数、环境变量、日志或家的备份。
  普通配置仅保留规范地址、五项绑定身份、名称、秘密存储类型与启停状态。
- worker 独立于本机后端和当前浏览的家。App 恢复已明确保存的配对；断线按 1～60 秒退避重连，
  退出 App 或父管道 EOF 则取消连接并回收子进程。本批没有长任务，也不重放动作。

配对 API 和连接协议 v1 保持兼容。WebSocket 握手支持 v1 与 v2，只有 v2 接受文件请求、结果和回执。
帧最多 256 KiB，严格拒绝重复键、NaN、错身份、错代次、未知字段和动作。新连接替换旧 generation。
已经发出的确认卡需要新的连接重新预览。

家里移除先持久收权，再通知本机；本机先持久禁用登记、删除秘密，再回撤销 ACK。
最多等 2 秒，无 ACK 不当成已收到。纯断线不是撤销；恢复后的旧凭据也无法重新认证。

## 身份与维护

公共 `home_instance_id` 保留原手机登记的持久 UUID，手机、账号登记和电脑使用同一来源；
已有值冲突或损坏失败关闭，不悄悄生成第二个家。所有者 subject 不使用名字、邮箱或路径派生。
旧家只在原所有者认证和明确迁移确认后建立 subject；新家和待认领的家不能凭 owner-key 文件越过认领。

认领及重新认领使用跨进程身份事务；开始重新认领先失效电脑信任。
账号和身份之间的认领完成 journal 允许原码、相同账号和密码在写入失败后幂等重试；
未完成的 journal 不授予电脑权限，后来重新认领也不能使旧 journal 重新生效。
备份恢复和搬家导入在暂存目录发布前生成全新随机 `trust_epoch` 并丢弃电脑授权，要求重新配对。
导出保留公共家身份，但不带电脑凭据；原来的手机迁移约定保持。

状态目录外的短维护锁与 Runtime 租约协同：启动在维护锁内取得长期租约，恢复、导入和搬走在同锁内
确认服务已停后交换目录。Web、独立 IM、heartbeat 的拥有者入口均使用共同 `RuntimeLease`，
避免恢复的目录切换空窗创建第二个 Runtime。

Desktop 的旧 raw tar 恢复也交给共同 runtime 维护入口，拒绝路径穿越、链接和含糊状态目录。
发布前同样轮换信任，只原子替换家状态，保留 home 根及维护锁 inode；当前状态移到旁边保留。
备份中的额外 home 文件私有地另存到 App 数据目录的 `recovered-extras-*`，不覆盖当前额外文件。
App 顶层的 owner-key、model.env 按原恢复约定保留当前值。原生备份文件从创建时即为 0600。

## API 与模块

| 接口 | 权限与行为 |
| --- | --- |
| `GET /api/computers/identity` | 仅公共持久家身份、协议区间与功能；不认领、不授权 |
| `POST /api/app/organizations/{org_id}/computer-pairings` | 已认证所有者生成短期码；普通成员、未配置令牌模式和跨站 Cookie 写入拒绝 |
| `DELETE …/computer-pairings/{pairing_id}` | 所有者作废未消费码 |
| `GET/PATCH/DELETE …/machines[/{machine_id}]` | 所有者读脱敏列表、改名、撤销；没有能力开放入口 |
| `POST /api/computers/pair` | 一次码兑换，严格核对家身份、大小、来源和家级速率；不接 Cookie 或所有者令牌 |
| `POST /api/computers/native-pair` | 只接从启动私有 stdin 交付的单次 Native 票据；直连字面回环 Host/peer，无 Cookie、Origin、查询串或转发头 |
| `WS /api/computers/ws` | 只收机器 Bearer；握手、心跳、撤销、ACK 与 v2 文件帧；拒绝 Cookie、Origin 和 URL 凭据 |

HTTP 响应 `no-store`，自鉴权只放行精确方法/路径。成员仍收到固定空电脑列表。
电脑令牌不能访问所有者、成员或手机接口。路由合同同步登记于原服务路由基线。

| 模块 | 职责 |
| --- | --- |
| `workflow/home_identity.py` | 公共 UUID、所有者 subject、认领及信任变更 |
| `gateway/connected_computers.py` | 私有持久配对码与机器摘要授权、限速、撤销 |
| `gateway/computer_protocol.py` | 有界协议协商，默认无文件权限 |
| `gateway/computer_connections.py` | 家侧控制连接、文件派发、代次隔离、撤销通知 |
| `gateway/computer_connector.py` | 独立拨出 worker、TLS、父进程生命周期 |
| `gateway/computer_file_process.py` | 小文件子进程、私有管道、截止与撤权 |
| `gateway/computer_file_tools.py` | 所有者的原 ToolRuntime 确认、预览绑定、结果污点 |
| `gateway/computer_file_intents.py` | 家侧派发意图及回执索引，不保存文件内容 |
| `gateway/computer_native.py` | 启动私有票据的摘要、真实父 PID、家与期限绑定，单次自动登记 |
| `utils/home_maintenance.py` | 状态目录外维护锁与通用进程文件租约 |
| `workflow/desktop_backup.py` | 旧 Desktop 备份安全恢复，共同信任失效与额外文件保留 |
| 自有 `desktop-dev` 的 `connector*.rs` | 可信本机窗口、原生确认、秘密存储与子进程管理 |

## 验证范围

离线测试覆盖跨进程迁移/兑换、重认领失败、恢复/搬家失效、维护与 Runtime 并发，
以及真实临时 HTTP/HTTPS/WS 连接、实际 FastAPI 与 worker 互通、两个打包入口的子进程、父 EOF、
撤销 ACK、协议/作用域拒绝、重定向和不信任证书拒绝。Rust 用 fake 秘密存储测试隔离、移除与撤销，
本机页面行为、前端类型及构建另行检查。
Python 3.10、3.12 分别验证控制协议与维护路径；专门使用 `asyncio.TimeoutError` 保持超时兼容。

本机回环使用真实 Web 服务、主要聊天确认卡与电脑 worker，验证读取、新建、预览差异、撤权、断线补报
和重复写入保护。测试用固定工具调用代表模型输出，并通过真实文件子进程验证中途断线续完、
在线撤销和进程崩溃后的未知状态。系统钥匙串和异地 Mac/Linux 双机仍需真机验收。
